## Qualifying this card

The card above was written by a non-technical user, most likely in Danish, and
you are in a checkout of the code it is about. Turn it into a GitHub issue a
developer can act on, then stop.

1. Read the card, its comments and every attachment listed above; the Read tool
   opens the images. Find the code and the screens it talks about.
2. Check the open GitHub issues for one that already covers it, with
   `gh issue list --search`. If one does, say so and stop rather than filing a
   duplicate.
3. Ask the person, in English, about whatever the card leaves unclear. One round
   of concrete questions, and nothing the code can tell you.
4. File the issue with `gh issue create`, in English, in the style of the repo's
   existing issues: a title, what happens, what should happen, steps to
   reproduce, pointers into the code, and the card's URL last.
5. Post the issue's URL back on the card as a comment, in the card's own
   language: `printf '%s\n' '<text>' | basecamp comments create <card id> -`.
6. Say what you filed. Fixing it is the next thing the person will ask for, in
   this worktree, so do not start on it unasked.
